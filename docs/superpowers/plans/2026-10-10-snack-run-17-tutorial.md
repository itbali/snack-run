# План 17. Обучение, помощь и переназначение клавиш — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal (просьба владельца 2026-10-10):** «добавить обучение + помощь/настройки, чтобы видеть и менять кнопки управления».

**Architecture:** `KeyBindings` (статический класс): список действий с русскими названиями, имя клавиши, переназначение
(клавиатурные события действия меняются, геймпад остаётся; занятая клавиша — обмен), сброс к `InputSetup.ACTIONS`,
сохранение в `user://settings.cfg` (загружается при старте `InputSetup`). Экран «Управление и помощь» (`ControlsMenu`,
CanvasLayer, работает на паузе): краткие правила игры, строки «действие — клавиша» (кнопка → «нажмите клавишу…», Esc —
отмена), «Сбросить», «Закрыть»; открывается из паузы и с заставки. Обучение (`Tutorial`, узел в `Main`): подсказки по шагам
внизу экрана с текущими клавишами — ходить, бежать, прыгать, подобрать еду, спрятаться, съесть, будка пряжи; шаг закрывается
действием; итог в сохранении (`GameState.tutorial_done`), повторно не показывается; «Пропустить обучение» в паузе.
Попутно: подсказка сытости после парка ведёт к порту (50), подписи «Закрыть (…)» берут текущие клавиши.

## Review Focus
1. Переназначение не ломает геймпад, не оставляет действие без клавиши, переживает перезапуск.
2. Во время ожидания клавиши Esc отменяет, а не ставит Esc; меню работает на паузе.
3. Обучение не мешает игре (без паузы), не повторяется после завершения или пропуска, сбрасывается «Новой игрой».
4. Подсказки показывают актуальные клавиши после переназначения.
5. Сохранения старых версий без `tutorial_done` грузятся (обучение для них — не показывать, если прогресс есть).
